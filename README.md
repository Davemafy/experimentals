# Video Appearance Lab

A small, standalone laboratory for comparing appearance-transfer and relighting compositions on **existing footage**.

The first experiment reuses a completed reference-frame image and a saved moving-subject mask video. It produces two graded variants and a four-way comparison contact sheet. It does **not** download models, start GPU inference, manage a remote service, or alter the input files.

## Inputs

Point `--jobs-root` to a directory of completed video-processing jobs. Each job must contain:

```text
<jobs-root>/<job-id>/
  source.mp4
  render/
    subject-aware.mp4
    ic-light-reference.png
    moving-subject-masks.mp4
```

The most recently completed job is chosen automatically.

## Dependencies

Python 3.10+, NumPy, OpenCV (`cv2`), and FFmpeg with `ffprobe` available on `PATH`.

## Usage

```bash
python video_appearance_lab.py \
  --jobs-root /path/to/completed-jobs \
  --output-root /path/to/experiment-output
```

Outputs go to `<output-root>/<job-id>/`:

- `balanced.mp4` — moderate source-detail-preserving lighting adjustment
- `dramatic.mp4` — stronger contrast and reference-derived color variation
- `comparison-contact-sheet.jpg` — start, midpoint, and end comparisons
- `experiment.json` — parameters and artifact paths

Source footage, reference image, mask video and baseline render are read-only. Existing experiment MP4s are never overwritten.

## Method and limitations

The script computes a low-frequency, per-channel log exposure difference between the original first frame and its edited reference. It applies bounded gain to source pixels with distinct foreground/background weights using previously generated masks.

This is **experimental appearance transfer**, not physically accurate relighting, temporal diffusion, or a matting improvement. The spatial gain remains anchored to the initial image and may not track moving subjects or camera motion correctly. Encoding success does not demonstrate better quality.

Review the entire exported video, not only the contact sheet. Pay attention to temporal flicker, matte boundaries, subject fidelity, background brightness and whether the look is actually more convincing.

No source media, credentials, rendered artifacts or service configuration belong in this repository.

## High-fidelity video-to-video trial (research stage)

`generative_video_lab.py` prepares three **different scene treatments** from a single original video. It does not generate an AI video until edited first-frame references and the upstream model are supplied.

| Scene | What changes | Conditioning |
|---|---|---|
| Golden Hour | Motivated sunlight, practical shadows, realistic haze | **Relight:** raw full original video |
| Silver Screen | Black-and-white photographic lighting, structured shadow | **Relight:** raw full original video |
| Neon Noir | Rebuilt night environment, motivated neon and atmosphere | **Restyle:** person-on-gray sequence from video segmentation |

**Research choice:** [ID-V2V](https://github.com/Eyeline-Labs/ID-V2V) (Eyeline Labs/Netflix). Its documented pipeline uses an edited first frame plus temporal video conditions, and distinguishes preserving the original background from regenerating it. Its official setup requires around **96 GB of model downloads**, and its published benchmark used eight A100 80 GB GPUs; single-GPU CPU-offloaded inference is documented but not validated here. Never assume a single 40 GB card will meet the full quality or speed target. [Official implementation](https://github.com/Eyeline-Labs/ID-V2V).

### 1. Prepare the three scenes, without model inference

```bash
python3 generative_video_lab.py prepare \
  --source /path/to/your-original-video.mp4 \
  --workdir /path/to/working-directory
```

Each folder contains `source.mp4`, `source_frame0.png`, `prompt.txt`, `reference_brief.txt`, and `scene.json`.

Use an image-editing system or artist to edit the **actual source frame** according to `reference_brief.txt`; maintain original actors' identities and poses. Save the edited image as `stylized_first_frame.png` in each scene folder. These reference images are **not generated by this script**. Reject impressive-looking reference frames that replace the actors, rearrange poses, add bodies or change camera geometry.

### 2. Check actual resources before downloading large checkpoints

```bash
python3 generative_video_lab.py status \
  --workdir /path/to/working-directory \
  --engine-root /path/to/separately-cloned/ID-V2V
```

**Important:** The full model assets plus working space may need significantly more than 100 GB disk. Do not launch checkpoint downloads just because a GPU is available. If another inference server is healthy on port 6006, this runner **refuses GPU execution** to avoid interfering with a shared production worker.

### 3. Model inference (only after the model, assets and reference are present)

Install upstream [ID-V2V](https://github.com/Eyeline-Labs/ID-V2V) **in a separate directory** following its own instructions, with enough disk and RAM. The runner never installs, downloads, edits, or restarts anything automatically. For restylization, run upstream SAM3 preprocessing first; this requires authorized checkpoint access and writes `preprocessing/orig_pixel.mp4` for the selected scene.

Then, **only on a dedicated GPU with no live worker sharing it**:

```bash
python3 generative_video_lab.py render \
  --workdir /path/to/working-directory \
  --engine-root /path/to/separately-cloned/ID-V2V \
  --scene golden_hour --confirm-gpu --timeout-minutes 50
```

The first trial is intentionally limited to **81 frames at 720p**, not a claimed finished five-second film. Run one scene, inspect it, then decide whether to attempt a longer clip. Failure, OOM and timeouts are not automatically retried.

### 4. Quality evidence and acceptance

```bash
python3 generative_video_lab.py evaluate \
  --workdir /path/to/working-directory \
  --scene golden_hour
```

The JSON report includes frame checks and temporal statistics but **never infers realism or identity preservation** from a valid MP4. To pass the optional human acceptance gate, rate **identity**, **performance fidelity**, **temporal stability**, **cinematography**, and **transformation** (0–20 each), and pass those values to `--ratings /path/to/ratings.json`.

Acceptance rule: **85/100 total, with at least 17/20 for identity, performance and temporal stability, and no objective warning flags**. These are product acceptance criteria, not independently validated perceptual metrics. Examine the entire generated video.

### Cost / deployment boundary

The official [hosted ID-V2V model](https://fal.ai/models/fal-ai/id-v2v) is another way to test the same research approach **without** an approximately 96 GB local checkpoint download. The listing currently quotes **$0.20 per generated video-second** (subject to change). Using it would require separate authorization and provider credentials; this repository does not connect to it.

No production deployment, hidden API key, model checkpoint or generated video is stored in this repository.
